# Cybersecurity game "MD5 Collision Attack Lab"

Linear game with **per-student flags (APG)** for the [CyberRangeCZ Platform](https://docs.platform.cyberrange.cz/).
Practical work (TP) of *System Security*, based on the SEED Labs "MD5 Collision Attack Lab" (Wenliang Du) and structured like
[`cyberrangecz/library-junior-hacker`](https://github.com/cyberrangecz/library-junior-hacker).

## Game levels summary

| # | Level | Points (/20) | Flag |
|---|-------|--------------|------|
| 0 | Introduction (info) | - | - |
| 1 | Get access (passkey `start`) | - | - |
| 2 | Task 1.1 - generate a collision from a personal prefix (`md5collgen`) | 3 | `flag_t1` |
| 3 | Task 1.2 - questions Q1, Q2, Q3 about the generated files | 3 | `flag_t1q` |
| 4 | Task 2 - MD5 property: `MD5(M\|\|T) = MD5(N\|\|T)` | 3 | `flag_t2` |
| 5 | Task 3.1 - locate the array in the ELF binary | 2 | `flag_t3a` |
| 6 | Task 3.2 - two executables, same MD5, different output | 4 | `flag_t3b` |
| 7 | Task 4 - benign / malicious programs with the same MD5 | 5 | `flag_t4` |
| 8 | Debrief and report (info) | - | - |

**Scoring.** The platform stores integers, so the game uses **half-points: 40 platform points = 20/20** (divide by 2).
Hint penalties are 1 to 4 platform points = **-0.5 to -2** on the /20 scale. If your platform version accepts decimals,
run `python3 tools/generate_training.py --decimal` to regenerate `training.json` with 20 points and penalties 0.5-2.

## Why students cannot cheat

* `variables.yml` makes the platform generate, **for every sandbox**, a random `student_id`, a random `prefix_len` and 6 random flags
  (`variant_sandboxes: true`, `variant_answers: true` in each level). Each student has a different `prefix.txt`, token, C sources and flags.
* Flags are **never on the student machine**. They live on the `authority` host (`/opt/authority`, root only) and are printed
  by the verification service **only if the student's own files pass the checks** (valid collision on *his* prefix, suffix with *his* token,
  binaries printing *his* token, ...). Files copied from a friend are rejected.
* Student binaries are executed by the authority as `nobody`, without network, with CPU/process/file limits.

## Topology

| Host | Image | Flavor | Role |
|------|-------|--------|------|
| seed | seed | m1.medium | student workstation (md5collgen, gcc, bless) |
| authority | debian-12-x86_64 | standard.small | certification authority (HTTP :8080) |
| router | debian-12-x86_64 | standard.small | routes `seed-switch` 10.1.27.0/24 <-> `authority-switch` 10.1.26.0/24 |

## Repository layout

```
topology.yml            hosts / networks
variables.yml           APG variables (random per sandbox)
training.json           training definition (generated by tools/generate_training.py)
provisioning/playbook.yml
provisioning/roles/seed        files given to the student, helper commands authority-upload / authority-verify
provisioning/roles/authority   verification server (files/server.py), systemd unit
tools/generate_training.py     regenerates training.json
```

## Import in CyberRangeCZ

1. Push this repository to GitHub (**private recommended**: `server.py` shows how the checks work; never publish the instructor solution).
2. *Sandbox definitions -> Create*: give the Git URL and the branch/revision.
3. *Training definitions -> Import* `training.json`; check that **Generate variant sandboxes** is ticked.
4. *Pool*: create a pool of **at least 30 sandboxes (+ spare)** from the sandbox definition; wait for provisioning. **Test one sandbox first.**
5. *Training instance*: link the training definition and the pool, release the definition, give the access token to the students.

## Things to adapt / verify at first deployment

* `topology.yml`: the **image name `seed`** and `mgmt_user: seed` must match your OpenStack image (the VM must allow SSH key login for Ansible and sudo).
* The SEED VM must contain `md5collgen`, `gcc`, `curl`, `bless`. If `md5collgen` is missing, put the binary in `provisioning/roles/seed/files/md5collgen`.
* The sandbox must let `seed` resolve/reach `authority:8080` through the router (handled by the platform topology like in the junior-hacker template).
* GUI login: `seed` / `dees` (set by provisioning). Change it in `provisioning/roles/seed/tasks/main.yml` and `training.json` if needed.
* Flag charset: flags are APG `password` variables of length 16; they are compared as exact strings.
